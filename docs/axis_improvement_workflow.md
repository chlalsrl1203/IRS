# 4축 개선 워크플로 (Axis Improvement Workflow)

**작성 2026-08-24.** 사용자 요청: "0.재무·회계 / 1.해자·펀더멘털·경쟁자 /
2.산업 현실·전망 / 3.경영진 자질 — 수정·보완·개선·발전할 때 어떻게 할지
워크플로를 세우고 실행해."

이 문서는 **새 프로토콜을 발명하지 않는다.** 이 프로젝트는 v3.52(구조적할인율
외부검증)·v3.63(스크리닝 기준)·v3.66(성장상한 base rate)에서 이미 같은 일을 세
번 했고 그 절차가 작동했다. 여기서는 그 절차를 **4개 축에 맞게 명시화**하고,
축마다 무엇이 다른지를 못박는다.

## 0. 먼저 — 왜 축마다 방법이 달라야 하는가

2026-08-24 코드 실측으로 확인한 각 축의 현재 상태:

| 축 | 현재 | 병목의 성격 |
|---|---|---|
| 0 재무·회계 | 계산 정확(골든재현 1e-12), **회계품질 판별 0** | **데이터는 있고 지표가 없었다** |
| 1 해자·경쟁자 | `moat`/`ROIC`/`invested_capital` 검색 히트 **0**. ROIC는 `BLOCKED` | **데이터가 아니라 정의 문제** |
| 2 산업 | `demand_sensitivity_pct` 숫자 하나 + 업종 앵커표 | **정량화 대상 자체가 모호** |
| 3 경영진 | 엔진 히트 0. `research_lenses`는 구조만, 실사용 **0건** | **데이터는 있는데 수집 계층이 없다** |

**네 병목이 전부 다르다.** 그래서 "외부 프레임워크를 하나 골라 다 적용한다"는
접근은 틀린다 — 축 0은 지표만 있으면 되고, 축 1은 지표를 만들어도 정의가
안 정해지면 못 쓰고, 축 3은 지표보다 수집 파이프라인이 먼저다.

## 1. 공통 관문 — 어느 축이든 이 8단계를 통과해야 한다

이 순서를 지키는 것이 핵심이다. **측정이 결정보다 먼저**여야 하고, **배선이
측정보다 먼저 오면 안 된다.** RQ-001이 후보 10개 중 2개만 ADOPT한 것, RQ-003이
순진한 발생액을 기각한 것 모두 이 순서 덕분에 잡혔다.

```
G1 공백 확정      코드 실측으로 "정말 없는가"를 확인한다. 문서/기억 금지.
                  (etf_engine.earnings_quality_score를 회계품질로 착각할 뻔한 사례)
      ↓
G2 외부 근거      1차 출처 우선. 서지정보와 계산식 본문의 검증 수준을 **분리 기록**.
                  PDF가 스캔본이면 파싱 실패를 그대로 적는다(TYL 2차출처 3배 오류 교훈).
      ↓
G3 안티기능 대조  §31 등록부와 충돌하는가? 특히 **합성점수**.
                  (F-Score·6차원 별점이 여기서 걸렸다)
      ↓
G4 도메인 확인    그 근거가 검증된 표본이 IRS 유니버스와 같은가?
                  (F-Score는 고 B/M 가치주 1976-96 — IRS는 FCF-DCF 성장주)
      ↓
G5 코퍼스 측정    34종목에 실제로 계산하고 **기존 지표와의 순위상관**을 잰다.
                  |rho|≥0.7 중복의심 / 0.4~0.7 부분중복 / <0.4 독립
      ↓
G6 결정           ADOPT / REJECT / DEFER / EXPERIMENT + 재개조건. 결정기록에 등재.
                  ⚠️ 측정 결과에 맞춰 임계값을 조정하지 않는다(사후합리화).
      ↓
G7 배선           opt-in · 병기 · 자동판정 안 함. 기본값 없으면 기존 동작 그대로.
                  성과 검증 0건이면 `run_analysis()`에 **배선하지 않는다**(독립 보관).
      ↓
G8 회귀검증       34종목 골든재현 8지표 + fingerprint 불변 + ledger 무수정.
                  ENGINE_VERSION 갱신(v3.32 규칙).
```

### G5의 판정 기준을 미리 고정한다

| 순위상관 | 판정 | 처리 |
|---|---|---|
| \|rho\| ≥ 0.7 | 중복 | **REJECT** — 기존 지표를 다른 이름으로 재도입하는 것 |
| 0.4 ≤ \|rho\| < 0.7 | 부분중복 | 원인 규명 후 재측정. 교란변수를 제거한 변형이 독립이면 그걸 채택 |
| \|rho\| < 0.4 | 독립 | ADOPT 후보 |

**이 컷은 실행 전에 고정했다.** RQ-003에서 순진한 발생액이 −0.717로 REJECT
구간에 떨어졌고, SBC를 되돌린 변형이 +0.200으로 ADOPT 구간에 들어왔다 —
결과를 보고 컷을 옮기지 않았다.

## 2. 축별 전략

### 축 0 — 재무·회계 : **지표 추가로 해결 가능** ✅ 1차 실행 완료

병목이 가장 얕다. 데이터(SEC XBRL)는 이미 있고 지표만 없었다.

| 후보 | 외부근거 | 판정 |
|---|---|---|
| 발생액 비율(SBC 되돌림) | Sloan(1996) TAR 71(3) | **ADOPT** — v3.70 구현 |
| Piotroski F-Score | Piotroski(2000) JAR 38 | **REJECT** — §31 합성점수 + 도메인 불일치 |
| Beneish M-score | Beneish(1999) FAJ | **DEFER** — 8개 변수 중 다수가 SEC 표준태그 밖 |
| 재작성(restatement) 이력 | — | **DEFER** — PHASE 5에서 재작성 8.5% 실측했으나 지표화 미검토 |

**L1 완료(RQ-004)**: 34종목 전수 1,256개 값 원인분류 — 미해결 67건(8종목) → **22건(1.8%)**.
**남은 것**: L2 확장(DSO 추세·재작성 이력 지표화), L3 확장(GAAP vs non-GAAP·리스).

#### 축 0 심층 구조 — 3개 층으로 나눠 본다 (2026-08-25 확장)

축0을 "지표 추가"로만 보면 토대를 놓친다. 세 층이고 **아래가 깨지면 위는 무의미**하다.

| 층 | 질문 | 상태 |
|---|---|---|
| **L1 데이터 정확성** | 숫자가 **맞는가** | RQ-004 완료 — 미해결 1.8% |
| **L2 회계 품질** | 숫자를 **믿어도 되는가** | RQ-003 발생액 1개 |
| **L3 표현 충실성** | 숫자가 **경제를 반영하는가** | SBC(v3.23) 1개 |

**L1 절차 — 불일치를 세지 말고 원인을 분류한다.** 가설을 하나씩 기계적으로 검정:

```
A 회계연도 라벨 시프트   ledger[Y] == SEC[Y±1] ?      52/53주 회계연도 오라벨
B 태그 정의 차이         좁은/넓은/+소프트웨어 ?       PHASE 3(MCK) 유형
C 재작성                 ledger == 최초 공시본 ?       PIT상 ledger가 맞을 수도
E 벤더 정규화            부호 반대 / ledger가 큼 ?     일회성 제외 의심
F 업종 구조              그 태그를 안 쓰는 업종 ?      보험사 OperatingIncomeLoss
D 원인 미상              위 전부 아님                  정직하게 남긴다
```

⚠️ **A는 SEC 값이 결측일 때도 반드시 검정한다.** 라벨 충돌은 두 기간이 같은
라벨을 다투다 한쪽이 조용히 사라지는 형태라 **결측 자체가 시프트의 증상**이다.
이 순서를 틀려서 A를 1건으로 과소집계했다가 고쳐 8건이 됐다(RQ-004 자체 발견).

**L1은 반드시 판정 영향까지 측정한다.** 불일치 건수는 그 자체로 의미가 없고,
"이 차이가 판정을 바꾸는가"만이 행동을 바꾼다. RQ-004 실측: BSX·CDNS에서 DRS가
+4.0 올라도 판정 뒤집힘 **0건**(DRS→ERP 압축 경로). ⚠️ 이걸 "데이터 정확성은
중요하지 않다"로 읽지 말 것 — 이번 표본에서 안 뒤집혔을 뿐이다.

**L2 진행 상황** (2026-08-26 RQ-005로 후보 둘 처리 — 전문:
`reports/research/RQ-005_l2_accounting_diagnostics_2026-08-26.md`):

| 지표 | 상태 | 커버리지 | 최대 |rho| |
|---|---|---|---|
| 발생액((NI−OCF+SBC)/평균총자산) | ADOPT (v3.70) | 34/34 | 0.200 |
| AR/매출 **상대**추세 | **ADOPT** (v3.71) | 30/34 | 0.240 |
| 재작성 이력 | **ADOPT, 이진 사실로** (v3.71) | 34/34 | 0.383 |

셋 다 **`run_analysis()`에 배선하지 않는다** — 투자 성과와의 관계가 IRS 표본에서
검증 0건이다. 독립성은 채택의 필요조건이지 배선의 충분조건이 아니다.

⚠️ **RQ-005가 확인한 세 가지 함정** (다음 후보에도 그대로 적용된다):

1. **단위를 절대 합치지 말 것.** 中 발행사는 같은 태그를 CNY·USD로 동시
   보고한다. 합쳐 비교했다가 PDD·TCOM 재작성률이 0.83~0.87로 나왔고, 편차가
   정확히 629.9%(=7.299 환율)로 반복돼 발각됐다. 분리 후 둘 다 0.000.
2. **수준에 비례하는 양을 그대로 비교하지 말 것.** AR 추세를 절대 %p로 재면
   TTD가 코퍼스 최대 이상치가 되는데, 원인은 회계 공격성이 아니라 광고중개업이
   채권을 총액·매출을 순액으로 잡는 구조다. 상대화하면 평범해진다.
3. **리포트는 엔진을 재현해야 한다.** 스크립트에 따로 구현했다가 채택 후 엔진과
   숫자가 갈렸다(VRT 0.217 vs 0.105). 사본을 지우고 엔진을 호출하도록 고쳤다.

**L2·L3의 남은 후보** (각각 G1~G8을 새로 통과해야 한다):
GAAP vs non-GAAP 격차 · 리스 자본화 · 충당금/대손 추세.
**아직 아무것도 측정하지 않았으므로 후보일 뿐이다.**

### 축 1 — 해자·경쟁자 : **정의를 먼저 정해야 한다** ⚠️

지표를 만들어도 못 쓴다. PHASE 4가 실측했다 — SEC로 자기자본·유효세율을 34/34
확보했는데도 **투하자본 정의 두 가지의 ROIC 비율이 중앙값 1.50배, 최대 206배**로
갈렸다(MCK 1347% vs 6.5%). 자기자본이 근사-0/음수인 유통업에서 분모가 폭발한다.

**따라서 이 축의 다음 작업은 지표 구현이 아니라 정의 확립이다:**

1. 외부 1차 출처에서 투하자본 정의를 확보한다. 우선순위:
   Mauboussin, *Measuring the Moat*(Credit Suisse/BlueMountain) — Base Rate Book이
   같은 계열이고 **직접 파싱에 성공한 선례**가 있다(v3.66). Damodaran의 ROIC
   조정 가이드가 차선.
2. 자기자본 근사-0/음수 기업 처리 규칙을 그 출처에서 가져온다. **자체 발명 금지.**
3. 정의가 정해진 뒤에야 G5 측정으로 간다.

⚠️ 정의를 확보하지 못하면 **DEFER를 유지한다.** "둘 중 하나를 고르자"는 근거
없는 선택이고, 이 프로젝트가 LYNCH_TYPE_CAPS·P/B 임계값에서 반복 거부한 형태다.

### 축 2 — 산업 현실·전망 : **정량화 자체가 미해결** 🔴

가장 어렵다. Porter Five Forces(HBR 1979/2008)가 표준 프레임이지만 **서술형**이라
`demand_sensitivity_pct` 같은 숫자로 환산할 검증된 경로가 없다. 억지로 점수화하면
§31 합성점수에 걸린다.

**실증된 실패가 이미 두 개 있다:**
- KEYS·KLAC — trailing CAGR이 AI 수요 인플렉션을 구조적으로 못 봄
- BKNG·PDD — 조회창이 짧아 반대 방향으로 틀림

둘 다 "산업 국면"을 못 본 사례다. 그런데 **둘 다 회사 자체 가이던스로는 잡혔다.**

**따라서 이 축의 현실적 다음 단계는 프레임워크 도입이 아니라 관측 확대다:**
회사 가이던스 vs 엔진 Realistic Growth 괴리를 체계적으로 수집한다
(`growth_scorecard`가 이미 그 구조를 갖췄고 관측 11건 보유). 관측이 쌓여야
"산업 국면 전환"이 무엇으로 드러나는지 알 수 있다.

**지금 프레임워크를 도입하지 않는다** — 무엇을 재야 하는지 모르는 상태에서
재는 도구부터 만드는 것이라서.

### 축 3 — 경영진 자질 : **수집 계층이 먼저다** 🟡

지표가 없는 게 아니라 **데이터를 가져오는 경로가 없다.** 그런데 데이터 자체는
SEC에 구조화돼 존재한다:

| 데이터 | 출처 | 상태 |
|---|---|---|
| 내부자 거래 | SEC **Form 4** | 구조화·무료. 수집 미구현 |
| 자사주매입 시점·가격 | 현금흐름표 + 주식수 | 부분 확보(PHASE 4에서 주식수 34/34) |
| 희석 추이 | `WeightedAverageNumberOfDilutedShares` | **확보됨**(PHASE 4) |
| 임원 보상·구성 | DEF 14A | 비구조화. 파싱 필요 |

**우선순위**: 희석 추이 → 자사주매입 규율 → Form 4. 앞의 둘은 이미 있는
데이터로 계산 가능하다.

⚠️ **PHASE 4의 경고를 반드시 승계할 것.** 희석 추이는 이미 한 번 틀린 결과를
배선했다가 철회한 이력이 있다 — 주식분할(TTD ×10.2)·ADS 비율변경(TCOM ×8.4)·
IPO 직후가 "희석"으로 잡혀 매수 유니버스 46.74%가 오염됐고, 정정 후 12.16%로
줄었다. **원자료 시계열을 눈으로 보기 전에 배선하지 않는다.**

외부 근거 후보: Thorndike, *The Outsiders*(자본배분 8사례) — 다만 사례연구라
정량 기준이 아니다. 내부자거래 문헌(Lakonishok & Lee 2001 등)이 정량 쪽.

## 3. 실행 순서와 그 근거

```
1차 ✅ 축 0 발생액        데이터·지표·근거 3박자가 다 갖춰진 유일한 축
2차    축 3 희석 추이      데이터 확보됨. 단 PHASE 4 오염 교훈 승계 필수
3차    축 1 ROIC 정의      외부 1차 출처 확보가 선행조건 — 못 구하면 DEFER 유지
4차    축 2 관측 확대      프레임워크가 아니라 가이던스 괴리 관측부터
```

**축 0을 먼저 한 이유**는 쉬워서가 아니라, 이 워크플로가 실제로 작동하는지를
**가장 빨리 검증할 수 있는 축**이기 때문이다. 그리고 실제로 작동했다 — G5에서
순진한 형태가 기각됐고(SBC 중복), 교란변수를 제거한 변형이 통과했다.

## 4. 이 워크플로가 지키는 불변조건

1. **측정 전 배선 금지.** 중복 여부는 코퍼스로만 알 수 있다.
2. **합성점수 금지**(§31). 개별 진단값만.
